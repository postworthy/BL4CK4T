# City Runtime

## Summary

The City Runtime is the common operating layer installed on many Cybertropolis desk terminals, service-room machines, public boards, permit counters, library checkout stands, clinic intake stations, and school work surfaces.

It exists because the city reused one familiar platform for many ordinary jobs. That reuse makes daily work easier to support, but it also means one known serious flaw can affect many different-looking systems.

## Story Function

- Gives Season 7 a clear equivalent for widely deployed vulnerable systems in the early-2000s worm era.
- Explains why a repair notice can matter to many offices, schools, clinics, and public counters at once.
- Keeps the story from forcing worm-era behavior through only Civic Pages signs.
- Lets episodes show patch debt, restarts, service interruption, emergency repair, and unauthorized repair through recognizable computing infrastructure.

## Reader-Facing Language

Use plain terms in public stories:

- City Runtime
- common runtime
- runtime version
- desk terminal
- service-room machine
- update track
- known repair

Avoid vague cabinet-language when writing public episodes.

## BL4CK4T Teaching Frame

The City Runtime teaches that common platforms create common responsibility. Shared technology can be efficient, but defenders need inventory, timely repair, tested rollback, and trusted update paths because one flaw may reach many places.

## Story Hooks

- A single repair notice affects many different-looking civic machines.
- A public board and a school desk terminal fail differently because they run the same old runtime.
- A service-room log shows the affected runtime version before anyone fully understands the pattern.

## Canon Notes

- The City Runtime does not replace the Civic Learning Grid, Message Office, Queue District, or Civic Pages District.
- It is an underlying software layer used across many civic systems.
- Season 7 is the first season where it becomes plot-critical.
