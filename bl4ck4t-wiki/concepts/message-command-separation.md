# Message-Command Separation

## Summary

Message-command separation is the Season 1 teaching concept behind the Echo Grid and Hushline. A user-facing message says something. A command or routing instruction changes what a system does. Trouble begins when a system lets ordinary messages and control instructions share a path that ordinary users can influence.

## BL4CK4T Teaching Frame

- Public messages and control instructions need different trust boundaries.
- A system can be beautiful, useful, and historically understandable while still having an unsafe architecture.
- A visible object or catchy rumor can distract from the actual design flaw.
- Durable fixes often separate paths instead of telling people to be more careful forever.

## Season 1 Story Mapping

- The Echo Grid is the old design where public service messages and routing instructions share a signal stream.
- The Little Blue Pawprint spreads sound and style without enough system context.
- The Crunch Charm becomes a myth object with no permission, account, authorization, or command power.
- The Tonebox safely models the difference between a mixed path and a separated path.
- The false closure shows how a wrong service message can affect public behavior.
- The Hushline separates public message paths from routing-command and control paths.

Avoid real telecom abuse detail, real frequencies, blue-box construction detail, exploit steps, or instructions for manipulating infrastructure.

## Story Hooks

- A public sign displays a false notice because an old message path touches a control path.
- A character mistakes a visible artifact for the cause when the real issue is architecture.
- A maintainer explains that the old design made sense in its time but should not remain trusted.
- A model shows the same message traveling safely after the command path is separated.
